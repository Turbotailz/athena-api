## Core Architecture

### Build-Time Database Pattern
This project uses a **static data architecture** with NO runtime database:

1. **Source of Truth**: Raw JSON files in `data/` (e.g., `heroes.json`, `items-by-locale.json`)
2. **Build Step**: `npm run build-data` runs `scripts/process-data.ts` which:
   - Reads raw JSON files
   - Downloads images from external URLs to `public/images/` (if not cached)
   - Normalizes stats using `STAT_MAPPING` 
   - Generates a single TypeScript file: `src/data/db.ts`
   - Auto-updates `package.json` version based on `data/patches.json`
3. **Runtime**: The API imports `src/data/db.ts` as an in-memory database

**CRITICAL**: Never edit `src/data/db.ts` or `src/data/types.ts` manually — they are generated artifacts.

### Dual Rendering Modes
- **Nuxt Framework**: Nuxt 4 with hybrid rendering
  - Static Site Generation (SSG) for documentation pages in `content/`
  - Server Routes for the REST API at `server/api/`
- **API Layer**: Native Nuxt Server Routes
  - Handles all `/api/*` endpoints
- **Hosting**: Cloudflare Pages (configured via `nitro.preset` in nuxt.config.ts)

### Key File Locations

#### Data Processing
- `data/` — Raw JSON files (community-editable source of truth)
- `scripts/process-data.ts` — Main build script that generates the database
- `src/data/db.ts` — **Generated** TypeScript database file (imported by API)
- `src/data/types.ts` — **Generated** TypeScript type definitions

#### API Implementation
- `server/api/` — REST API implementation
  - Imports `DATA` from `src/data/db.ts`
  - Returns JSON responses for heroes, items, powers
  - Supports query params (`role`, `type`, `rarity`) and expansion (`expand=items,powers`)

#### NPM Client SDK
- `src/lib.ts` — Public exports for NPM package
- `src/client.ts` — `OverwatchHeroClient` class for consuming the API
- `src/mcp.ts` — Model Context Protocol server for AI integration

#### Documentation Site
- `content/` — Markdown documentation pages (Nuxt Content)
- `app/` — Nuxt 4 application structure (Vue components, layouts, pages)
- `app/components/` — Vue components usable in Markdown via MDC syntax (e.g., `::hero-list`)

## Development Workflows

### Updating Game Data
To add a hero or fix item stats:
1. Edit the appropriate JSON file in `data/` (e.g., `heroes.json`)
2. Run `npm run build-data` to regenerate `src/data/db.ts`
3. Commit **both** the raw JSON and generated files

### Adding API Endpoints
1. Create or edit files in `server/api/`
2. Use typed data from `src/data/db.ts`
3. Export response types in `src/lib.ts` for SDK consumers
4. Test locally with `npm run dev`

### Modifying Documentation
1. Edit or create `.md` files in `content/`
2. Use MDC components for dynamic content (e.g., `::hero-list`)
3. Nuxt Content will auto-render changes in dev mode

## Technical Constraints

### Image Handling
- Images are downloaded during `npm run build-data` and cached in `public/images/`
- **Never commit binary images** — they are fetched from source URLs in the JSON
- The script respects rate limits (50ms delay between downloads, 5s retry on 429)

### TypeScript Configuration
- Extends `.nuxt/tsconfig.json` (generated by Nuxt)
- Strict mode enabled
- All source files must be strongly typed

### ESLint Style
- Configured via `@nuxt/eslint`
- Stylistic rules: `commaDangle: 'never'`, `braceStyle: '1tbs'`
- Run `npm run lint` before committing
